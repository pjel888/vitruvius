## Custody Model

### Layer Responsibilities

| Layer | Purpose | Admission Gate |
|-------|---------|----------------|
| `001_Raw-Source-Layer/` | Immutable original custody (PDFs, scans) | None — append-only |
| `002_Raw-Conversion-Layer/` | Extraction staging (Markdown, JSON, OCR) | Pipeline output |
| `003_Canonical-Knowledge-Layer/` | Trusted canonical artifacts only | Human reviewer + steward approval |
| `006_System-Manifests/resource-layer/` | Resource registry and node-resource links | Reviewer workflow |

### Draft Artifact Rule

**Draft study aids must NOT remain in the Canonical Knowledge Layer.**

Options for draft artifacts:
1. Keep in `002_Raw-Conversion-Layer/` (preferred)
2. Move to a new `002_Raw-Conversion-Layer/staging/` directory
3. Delete if redundant with conversion-layer originals
4. Gitignore ephemeral pipeline outputs

### Source Markdown Admission Workflow

```
Raw source (001) → Conversion (002) → Review → Canonical (003) or Resource Layer (006)
                                     ↘ Reject → Archive or delete
```

### Required Metadata Before Admission

Before a source markdown becomes a canonical artifact or Resource Layer entry:

| Field | Required? | Source |
|-------|-----------|--------|
| `id` | Yes | Assigned by registry |
| `title` | Yes | Human-verified |
| `resourceType` | Yes | Human-classified |
| `sourceFamilyId` | Yes | Matched to known family |
| `localFileHash` | Yes (local files) | SHA-256 at indexing time |
| `localPath` | Yes (local files) | Relative path |
| `rightsStatus` | Yes | Human-reviewed |
| `sourceRights.canStore` | Yes | Legal review |
| `verificationStatus` | Yes | At least `metadata_verified` |
| `jurisdiction` | If applicable | Truthful, not guessed |
| `edition` / `publicationYear` | If applicable | Truthful, not guessed |

### Hash and Provenance

- Local files are hashed at indexing time by `api/resourceLayer/localCorpusScanner.ts`.
- Hashes are stored in `local-file-index.json`.
- If a file changes, the hash mismatch is detected on re-index.
- Re-indexing does NOT auto-update Resource Layer entries; reviewer decision required.

### Gitignore Recommendations

Current `.gitignore` already ignores `/001_Raw-Source-Layer`.

Consider adding to root `.gitignore`:
```
# Pipeline ephemeral outputs
003_Canonical-Knowledge-Layer/shared/sources/*.draft.md
002_Raw-Conversion-Layer/**/*.auto-generated.md
```

**Do NOT gitignore the entire `003_Canonical-Knowledge-Layer/shared/sources/` directory** because it contains legitimate tracked canonical sources.

### Rights/Source Provenance

For each source, record:
- Where it came from (scan, download, donation, purchase)
- What rights are known (public domain, licensed, fair use, internal)
- What usage is permitted (quote, link, store, distribute)
- Who reviewed the rights assessment
- When it was reviewed

### Preventing Accidental Staging

- Conversion pipeline outputs should write to a clearly named staging directory.
- Staging directory should be gitignored or cleaned periodically.
- Reviewer workflow should be the ONLY path from staging to canonical/Resource Layer.
- Automated linking of local files to graph nodes is PROHIBITED without reviewer approval.

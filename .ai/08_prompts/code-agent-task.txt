--- A-2. Relationship Type Registry ---
File to create:
  - scripts/vitruvius/rules/relationship_registry.yaml

Shape (exactly this):
```yaml
schema_version: 1.0.0
predicates:
  governs:
    allowed_pairs:
      - {subject_type: source, object_type: concept}
  defines:
    allowed_pairs:
      - {subject_type: source, object_type: concept}
  requires:
    allowed_pairs:
      - {subject_type: concept, object_type: concept}
      - {subject_type: concept, object_type: attribute}
  depends_on:
    allowed_pairs:
      - {subject_type: concept, object_type: concept}
  limits:
    allowed_pairs:
      - {subject_type: source, object_type: concept}
      - {subject_type: source, object_type: attribute}
      - {subject_type: section, object_type: concept}
      - {subject_type: section, object_type: attribute}
  affects:
    allowed_pairs:
      - {subject_type: concept, object_type: concept}
      - {subject_type: source, object_type: concept}
  supersedes:
    allowed_pairs:
      - {subject_type: source, object_type: source}
      - {subject_type: concept, object_type: concept}
```

--- A-3. Promotion Validator ---
File to create:
  - scripts/vitruvius/promotion_validator.py

Interface:
```python
from dataclasses import dataclass
from typing import List

@dataclass
class ValidationResult:
    passed: bool
    errors: List[str]       # empty if passed
    record_id: str          # relationship ID or candidate fingerprint

def validate_promotion_record(record: dict, registry: dict, canonical_index: dict) -> ValidationResult:
    """Apply all 17 rules from relationship-schema.md §10. Never raise on
    validation failures — return them as errors. Raise only on unexpected
    system errors (e.g., corrupt YAML)."""
```

Tests (pytest-style, in scripts/tests/test_promotion_validator.py):
  - One valid record passes.
  - Unknown predicate fails rule 4.
  - Missing source_section_id on an evidence entry fails rule 8.
  - Incompatible subject/object pair for the predicate fails rule 7.
  - confidence_score below 0.90 (first-time promotion) fails rule 13.

--- A-4. run_promote + promotion.py ---
File to create:
  - scripts/vitruvius/promotion.py

Entry point: `run_promote(execute: bool, rollback_batch_id: str | None) -> int`

Flow:
1. Load `latest_relationship_review_high_confidence.json`. If missing, print a
   helpful error and return 1.
2. Load the registry, the source index (walk 003/shared/sources), and the
   concept index (walk 003/shared/concepts).
3. For each reviewed candidate:
   a. Build a provisional relationship record per relationship-schema.md §4.
   b. Compute the relationship ID: `rel-<slug>` where slug is
      `slugify(f"{from_entity}-{predicate}-{to_entity}")`.
   c. Check if the file already exists. If yes, load it, merge evidence per
      §6, and recompute confidence_score as the minimum across all evidence.
   d. Validate via promotion_validator.
   e. If valid and --execute, write the file.
   f. Record outcome in the audit log (per-record: accepted / merged /
      rejected + reason).
4. Generate promotion_batch_id = `{utc_stamp}_{short_hash}`.
5. Write 006_System-Manifests/runs/latest_promotion_audit.log and a timestamped
   copy.
6. Print a summary to stdout.

Register in pipeline_cli.py as:
  `python scripts/pipeline_cli.py promote [--execute] [--rollback BATCH_ID]`

Rollback mode (--rollback):
- Load the audit log for the specified batch_id.
- For each write recorded in that batch, either delete the file (if it was
  created in that batch) or remove the merged evidence entries (if it was
  updated). Leave the audit log in place, add a rollback entry.
